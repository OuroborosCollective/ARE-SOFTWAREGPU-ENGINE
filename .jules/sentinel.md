## 2024-03-24 - [CRITICAL] Added explicit JSON payload limit and parameter structure boundary checks to Android local IPC socket server subsystem.
**Vulnerability:** Missing request schema and limits boundary check. The `AndroidIPCServer` deserialized unsanitized UDS local requests using JSON without validating length limits, schema fields or input bounds using `validate_request` from `security.py`.
**Learning:** Even loopback-bound Unix domain sockets intended for local IPC must defensively validate request payloads using the existing security boundaries, otherwise any local user could send malformed requests causing application crash/resource exhaustion, or bypass method/parameter restrictions.
**Prevention:** Always wrap request unmarshalling paths, including local sockets/IPC, with the application's central `validate_request` contract bounds enforcement.
## 2026-11-08 - [MEDIUM] Secure Network Output via In-Memory Framebuffer Serialization
**Vulnerability:** The `op_render_mesh` RPC endpoint serialized output frames to temporary files (`tempfile.NamedTemporaryFile`) on the worker filesystem before reading them back for Base64 encoding. This creates an unneeded filesystem touch in a network service handling arbitrary remote RPC rendering jobs, increasing I/O overhead and exposing temporary files.
**Learning:** Network endpoints returning image/binary payloads should exclusively use in-memory encoding (like native Python struct/bytes manipulation for BMPs) instead of caching to disk to eliminate filesystem traversal points or disk capacity exhaustion risks when serving concurrent requests.
**Prevention:** In RPC dispatchers, avoid `os.path` and `tempfile` when generating immediate responses. Format payload bytes completely in RAM using `io.BytesIO` or `struct` bindings from existing data buffers.
