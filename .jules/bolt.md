## 2026-10-13 - Blinn-Phong fragment contract audit
**Finding:** Converting a NumPy float32 UV coordinate to a Python float before multiplying by the texture extent can alter truncation at a texel boundary, so byte parity does not hold for the proposed float conversion.
**Change:** Keep native NumPy UV arithmetic, read the mutable texture once per fragment, and add differential texel-boundary and in-place-resize tests.
**Evidence:** Previous draft head 89e126b CI passes (CPU regressions 38452257413, Mesa 38452257025). A controlled new head-versus-main performance gain is *not* established; no general speedup claim.
## 2026-10-14 - Scalar replacement of numpy routines in shaders requires exact boundary condition testing
**Learning:** Pure scalar alternatives to Numpy operations (like `np.clip`) are extremely effective performance optimizations for heavily iterated per-pixel functions like `fragment_shader`, reducing calling overhead. However, when replacing array math, be aware that python scalar math handles floating point conditions like `NaN` silently (unlike numpy logic which relies on numpy internal conversion failure on array to int transitions). This causes exact bound/byte-parity tests relying on failing fast to break.
**Action:** When replacing Numpy routines with manual scalar math loops in strict numerical pipelines, explicitly check variables against `math.isnan()` to safely throw `ValueError` exactly matching the original exception contract for byte parity backwards compatibility.
