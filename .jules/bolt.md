## 2026-10-13 - Blinn-Phong fragment contract audit
**Finding:** Converting a NumPy float32 UV coordinate to a Python float before multiplying by the texture extent can alter truncation at a texel boundary, so byte parity does not hold for the proposed float conversion.
**Change:** Keep native NumPy UV arithmetic, read the mutable texture once per fragment, and add differential texel-boundary and in-place-resize tests.
**Evidence:** Previous draft head 89e126b CI passes (CPU regressions 38452257413, Mesa 38452257025). A controlled new head-versus-main performance gain is *not* established; no general speedup claim.
## 2026-10-14 - Faster bounding with pure scalar float functions vs np.clip in hot loops
**Learning:** `np.clip` involves slow internal Python dispatches that become a major bottleneck inside highly iterated, per-pixel hot paths like `BlinnPhongShader.fragment_shader`. While pure float scalar bounds (`min`/`max`) provide a nearly 2x speedup and match the desired calculation exactly, `min` and `max` swallow `NaN` values whereas `np.clip` surfaces them. This violates exception contracts in byte-parity and exact-bound tests (e.g. `test_nonfinite_material_does_not_become_valid_white_or_black`).
**Action:** Replace `np.clip` with float `min`/`max` when extreme performance is required in hot loops, but explicitly add a `math.isnan()` check on the values before clamping to preserve exact `NaN` exception contracts required by the test suite. Also, remember to import `math` at the module level rather than inside the hot loop to avoid overhead.
