## 2026-10-13 - Blinn-Phong fragment contract audit
**Finding:** Converting a NumPy float32 UV coordinate to a Python float before multiplying by the texture extent can alter truncation at a texel boundary, so byte parity does not hold for the proposed float conversion.
**Change:** Keep native NumPy UV arithmetic, read the mutable texture once per fragment, and add differential texel-boundary and in-place-resize tests.
**Evidence:** Previous draft head 89e126b CI passes (CPU regressions 38452257413, Mesa 38452257025). A controlled new head-versus-main performance gain is *not* established; no general speedup claim.
## 2024-05-18 - Replacing Numpy Operations with Pure Python in Hot Paths
**Learning:** Converting numpy array functions like np.clip to pure python scalar operations (e.g. min, max, +) in the hot path of fragment_shader improves performance while maintaining exact byte-parity. However, be careful as min/max swallows NaN, so we must maintain original behavior by reverting that change or manual exception handling. Multiplying by a python float inside the fragment shader is fast, but using an explicit `astype(np.float32, copy=False)` on the sampled texture first while converting the rest to a python tuple is faster without breaking parity tests.
**Action:** Identify hot paths heavily calling numpy operations inside loops and convert them to pure python equivalents while preserving behavior on edge cases and test parity.
