# Verified versioned releases and announcements

GoReleaser OSS is a **separate** semver release lane. It does not replace
`.github/workflows/android-gradio-apk-release.yml`, which builds SHA-specific
Android debug APK and portable Node preview clients and publishes the npm
package to GitHub Packages.

## Release procedure

1. Merge the reviewed change containing `.goreleaser.yaml`, workflow, release
   gate and regression tests **only after full exact-head CI is green**. Keep
   `Memory.md` as an append-only record of change, learning and evidence.
2. Confirm the exact `main` commit has a successful **push** run of the existing
   `CPU regressions` workflow, with at least all its eight matrix/package/UI
   jobs green. A green PR, manual dispatch or older run does not qualify.
3. Match the version in `setup.py` to a strict semantic tag such as `v1.2.0`.
   Tag the **same reviewed main commit** and push the tag. No release is made
   merely by merging or by running tests. Avoid reusing published tags.
4. On tag push, the workflow checks source ancestry, reads GitHub Actions jobs
   for the exact SHA, builds the wheel with `LICENSE.md` and `NOTICE`, tests
   GoReleaser config, publishes source + wheel + checksums and reads back
   the actual GitHub Release. Failed gates block publication.
5. Confirm published assets, checksums and the GitHub Release target/commit.
   Treat CI success without these readbacks as incomplete evidence.

The release is CPU-first **research software**, licensed PolyForm
Noncommercial 1.0.0 (source-available, NOT unrestricted open source).
A wheel is Python software, NOT a native Windows GPU, Android APK or
production-ready publicly exposed Gradio server. No FPS or hardware-GPU
performance promises should be made in announcements.

## Publicity and DEV.to

The GitHub Release is publicly visible on success and automatically contains
release notes/changelog generated by GoReleaser. If both optional GitHub
Actions secrets `DISCORD_WEBHOOK_ID` and `DISCORD_WEBHOOK_TOKEN` are configured,
GoReleaser also posts its release announcement in that Discord webhook.
Without those secrets it publishes **no Discord message**. Do not put webhook
values in commits, logs or issues; never post to third-party communities without
an authorized account.

The existing `.github/workflows/devto-articles.yml` / `tools/devto_publish.py`
remains the separate reviewed DEV.to publishing path; it is **not** automatically
triggered by these releases and does not create per-tag articles. Its latest
observed real API response was HTTP 403 and the actual API-key/readback blocker
must be resolved independently before any claim of public DEV.to promotion.
Do not weaken DEV.to's human-publication gate to work around that blocker.

## Evidence and rollback

A pull-request run performs a real GoReleaser *snapshot only*: `goreleaser check`
and `goreleaser release --snapshot --clean`, producing local checksums and a
source archive without contacting publishing endpoints. The tag release runs
only after the exact SHA's main CI evidence passes. To disable future semver
releases, disable `Verified GoReleaser release` or revert its workflow/config.
Existing published releases remain and must be handled explicitly; do not
rewrite existing immutable tags or remove release assets silently.
