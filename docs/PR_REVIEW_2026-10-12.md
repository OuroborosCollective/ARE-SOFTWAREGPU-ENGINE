## Shader counterexample

`evidence/pr-shader-review-2026-10-12.json` binds each tested candidate head and shader source hash. With float32 zero normal/UV, diffuse `[1,1,1]`, specular `[0,0,0]` and NaN ambient material, the current reference raises `ValueError`; nine candidates emit white and #44 emits black. Candidate modules were executed directly from their Git objects. The 254 ordinary ambient boundary samples in this probe did **not** differ; this evidence makes no claim that they did. No candidate throughput numbers are accepted as justification for changing numerical/error contracts.

## Integration boundaries

Both accepted changes remain explicit opt-ins. Default backend is still `tiles`, preparation caching is disabled by default. Cache storage contains derived setup only; current depth, coverage and fragment work execute again. Native raster accepts only the exact built-in VertexColor methods, uses one native call per draw and does not run a Python fragment loop. Mesh preparation/clipping/packing remain outside that C++ kernel.

Conflicts in rasterizer construction and draw dispatch were resolved to retain both independent paths. Cache activation on `native-cpp` is rejected and covered by a real-kernel regression. All coverage floors are retained, including both new 95% module floors and the existing symbolic floors. The symbolic timing test retains a strict positive duration and uses 1,024 actual frame pairs; the new `direct-checked` mode is tested.

The shared `native/symbolic/core.hpp` change extracts existing validation unchanged and adds DirectEngine. This invalidated the bio builder's deliberate exact-core pin. After reviewing that delta, the pin was advanced to `6728fedbef7f48f9db8e02d3ee082136c89f18ce83195b1bbcd1a4af348ac649`; corruption rejection and the independent renderer oracle remain in the tests. Frozen workroom fixture bytes and all historical evidence hashes are unchanged. Historical timings continue to describe their original source versions.

Existing main Memory bytes remain an identical prefix; the previously separate #35/#31 history is retained, followed by one new integration entry. This integration does not publish original GLB binaries, change deployment, enable a default cache, or claim hardware-GPU parity.
